# راهنمای افزودن قابلیت

مثال: افزودن امکان ثبت تماشای دستی.

1. **رفتار را بنویسید:** ثبت تماشا به Movie مربوط است، نه MediaFile؛ اجرای پلیر خودکار آن را ثبت نمی‌کند. تکلیف تاریخ، منطقهٔ زمانی و تکرار ثبت روشن باشد.
2. **مالک را مشخص کنید:** ماژول personal؛ دسترسی به هویت فیلم از قرارداد library.
3. **مدل و migration:** فقط اگر نیاز جدید است. قیود تکرار و provenance را تعیین کنید.
4. **قرارداد ورودی/خروجی:** schema مشخص؛ ORM object به UI نشت نکند.
5. **منطق Service:** وجود فیلم، قواعد ثبت، تراکنش و خطاهای کاربردی؛ مستقل از HTTP.
6. **Repository:** عملیات لازم برای persistence، بدون commit پراکنده.
7. **Router:** اعتبارسنجی HTTP و اتصال وابستگی‌ها؛ بدون قواعد تماشا.
8. **تست:** مسیر موفق، فیلم ناموجود، ورودی نامعتبر، اجرای دوباره و rollback.
9. **مشاهده‌پذیری:** رخداد مناسب و شناسه‌ها؛ متن یادداشت شخصی بی‌دلیل لاگ نشود.
10. **مستندات و بازبینی:** API، README ماژول و تصمیم معماری فقط اگر واقعاً تغییر کرده‌اند.

اگر فیچر طولانی است، Service یک Job ثبت کند و handler پس‌زمینه آن را اجرا کند. اگر به سرویس بیرونی نیاز دارد، Adapter و fake آزمایشی اضافه کنید؛ وابستگی جدید را مستقیم وارد Router نکنید.

README هر ماژول باید کوتاه پاسخ دهد: مالک چه داده‌ای است؟ عملیات عمومی چیست؟ به چه قراردادهایی وابسته است؟ قواعد ثابت و تست‌های مهم کدام‌اند؟
