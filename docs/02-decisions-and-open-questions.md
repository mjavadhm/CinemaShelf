# وضعیت تصمیم‌ها و پرسش‌های باز

این دسته‌بندی از قطعی جلوه‌دادن پیشنهادهای گفتگو جلوگیری می‌کند.

## جهت‌گیری‌های پذیرفته‌شده در گفتگو
- استفاده از FastAPI برای بک‌اند.
- معماری سبک و قابل‌گسترش: مونولیت ماژولار، Service Layer، Repositoryهای ساده و Adapterهای خارجی.
- جداسازی کارهای طولانی از درخواست HTTP؛ نگهداری وضعیت کارها در دیتابیس.
- اضافه‌شدن لاگ‌گیری متمرکز و ساختاریافته به طراحی.

## پیشنهادهای فنی مبنا، قابل بازبینی پیش از اجرا
- SQLite + SQLAlchemy و Alembic.
- Pydantic برای قراردادهای API؛ logging استاندارد پایتون برای لاگ.
- یک پردازش API و یک اجراکنندهٔ کنترل‌شدهٔ کارها در نسخهٔ محلی اولیه.
- polling برای پیشرفت؛ SSE تنها در صورت نیاز.
- Ruff، mypy، pytest و CI.
- پروژهٔ جدید، با استفادهٔ مجدد کنترل‌شده از کد قدیمی.
- ساخت هستهٔ منابع و کتابخانه پیش از اتصال کامل دانلودر.

## پرسش‌های باز
| موضوع | پیشنهاد فعلی | اثر و زمان تصمیم |
|---|---|---|
| سیستم‌عامل هدف | مشخص نشده | پیش از پیاده‌سازی پخش، مسیرها و هویت هارد |
| پروژهٔ جدا یا تغییر پروژهٔ فعلی | پروژهٔ جدا | پیش از ایجاد مخزن و ساختار اجرایی |
| دامنهٔ اولین تحویل | پایه، منابع، اسکن، کتابخانه، تماشای دستی | پیش از برنامه‌ریزی مرحلهٔ اول |
| تعارض دادهٔ محلی و Letterboxd | ویرایش دستی بی‌اجازه بازنویسی نشود | پیش از نوشتن همگام‌سازی |
| منبع metadata و پوستر | بررسی دسترسی، شرایط و پوشش | پیش از پیاده‌سازی provider واقعی |
| داده‌های قابل استخراج Letterboxd | نمونهٔ آزمایشی مرورگر واقعی | پیش از تعهد قابلیت آنلاین |
| هویت هارد و تغییر mount/drive | وابسته به OS | پیش از نهایی‌کردن مدیریت منابع |
| پلیر پیش‌فرض و مسیر سفارشی | پیش‌فرض سیستم + تنظیم اختیاری | پس از تعیین OS |

نبود نتیجهٔ یک فیلم در اجرای ناقص همگام‌سازی، مجوز حذف وضعیت تماشای آن نیست. واچ‌لیست، watched، ratings و diary چهار مفهوم متمایزند.

## نسخه‌های وابستگی‌ها
در این بسته نسخهٔ Python و وابستگی‌های پروژهٔ جدید قفل نشده‌اند. در شروع توسعه نسخهٔ پشتیبانی‌شده انتخاب، محیط آزمایش و نسخه‌ها در فایل وابستگی و lock ثبت شوند. وابستگی‌های قدیمی را بدون بررسی به پروژهٔ جدید منتقل نکنید.
