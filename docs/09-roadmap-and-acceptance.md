# ترتیب اجرا و معیارهای پذیرش

## گام صفر: تأیید و آزمایش
OS، مخزن جدید و دامنهٔ اولین تحویل تأیید شوند. مدل هویت منابع و فیلم‌ها مرور شود. نمونهٔ Letterboxd و بررسی provider metadata موازی و جدا از هسته انجام شوند؛ موفقیتشان فرض گرفته نشود.

## گام یک: یک برش انتهابه‌انتها
تنظیمات، logging، DB session، migration اولیه، error handler و تست پایه. سپس معرفی یک Source → ثبت Job اسکن → ثبت MediaFile → API نمایش نتیجه. این برش باید بدون اینترنت و بدون جابه‌جایی فایل کار کند.

## گام دو: کتابخانهٔ قابل استفاده
چند منبع، اصلاح دستی تطبیق، چند نسخه، جست‌وجو و فیلتر، وضعیت دسترسی، پخش مطابق OS، ثبت دستی تماشا و امتیاز، CSV Letterboxd. جزئیات رابط و قرارداد API با مصرف‌کننده هماهنگ شوند.

## گام سه: غنی‌سازی و همگام‌سازی
metadata و cache پوستر، همگام‌سازی مرورگرمحور پس از آزمایش موفق، سیاست تعارض، سابقهٔ تماشا و مدیریت بهتر تغییر مسیر منابع.

## گام چهار: ادغام دانلودر
صف واحد فوری/زمان‌بندی‌شده، JIT، بررسی موجودی، reconciliation با Aria2 و دیسک، ورود فایل تکمیل‌شده و retry امن. LLM افزونهٔ اختیاری باقی بماند.

## معیارهای تحویل هسته
- فیلم در چند منبع با یک جست‌وجو پیدا شود و نسخه‌ها روشن باشند.
- تکرار اسکن و import، دادهٔ تکراری ایجاد نکند.
- قطع هارد اطلاعات را حذف نکند؛ نبود فایل روی هارد متصل متمایز باشد.
- اسکن نیمه‌تمام باعث مفقودشدن گستردهٔ فایل‌ها نشود.
- وضعیت تماشا مستقل از نسخه/منبع باقی بماند.
- کتابخانه بدون اینترنت قابل مرور باشد.
- هیچ فایل اصلی بدون تأیید جابه‌جا یا حذف نشود.
- restart منجر به scheduler تکراری، دانلود مجدد ناخواسته یا state دروغین نشود.
- لاگ و پاسخ API دادهٔ حساس نداشته باشند.

## ترتیب استفادهٔ مجدد
ابتدا دامنه و تست؛ سپس کد قدیمی مناسب را پشت Adapter منتقل کنید. هدف انتقال فایل‌به‌فایل یا حفظ تمام رفتارهای قدیمی نیست. تغییر آرشیو اصلی و migration دادهٔ کاربر باید مرحلهٔ مستقل با backup و گزارش باشد.
