# قراردادهای توسعه و کیفیت

## خوانایی
نام‌ها انگلیسی و معنادار؛ type hint برای مرزهای عمومی و قراردادها. زبان پیام‌های UI فارسی، کد و نام رخدادها انگلیسی. کامنت دلیل را توضیح دهد، نه تکرار خط کد. docstring برای قرارداد و رفتار غیرمنتظره؛ برای هر تابع ساده توضیح اجباری ننویسید.

توابع مسئولیت محدود داشته باشند. فایل بزرگ را بر اساس مفهوم تقسیم کنید، نه عدد دلخواه خط. abstraction فقط وقتی مسئلهٔ واقعی یا مرز وابستگی دارد. از پوشهٔ utils برای کد نامرتبط استفاده نشود.

## تنظیمات و lifecycle
مسیر داده، DB، cache پوستر، log، پروفایل مرورگر و دانلود در یک سیاست تنظیمات مرکزی مشخص باشند؛ به cwd تصادفی وابسته نباشند. نمونهٔ تنظیمات بدون secret ارائه شود. startup/shutdown واضح؛ import بدون side effect.

توابع blocking مربوط به دیسک، مرورگر و subprocess روی event loop اجرا نشوند. نوشتن `async def` به‌تنهایی کد blocking را غیرمسدودکننده نمی‌کند. انتخاب sync/async بر اساس وابستگی‌ها باشد؛ async کردن همهٔ Repositoryها الزام نیست.

## ابزارها
Ruff برای format/lint، mypy با سخت‌گیری تدریجی، pytest برای تست، Alembic برای migration. نسخه‌ها و دستورهای قطعی پس از ایجاد pyproject و lock ثبت شوند؛ این بسته config اجرایی تولید نکرده است.

یک دستور واحد پروژه برای check در نظر بگیرید که lint، type-check و test را اجرا کند. CI همان دستورها را اجرا کند؛ تست مرورگر زنده یا شبکه شرط تست واحد نباشد.

## تست‌ها
- واحد: قواعد تطبیق، انتقال وضعیت، زمان‌بندی شامل عبور از نیمه‌شب، deduplication و تعارض داده.
- یکپارچه: Repository با SQLite واقعی موقت، migration، API با وابستگی‌های تستی.
- فایل‌سیستم: مسیرهای موقت، چند نسخه، اسکن دوباره، قطع منبع و شکست دسترسی.
- Adapterها: fake/stub و نمونهٔ پاسخ پاک‌سازی‌شده؛ تست زنده جدا و opt-in.
- معماری: ممنوعیت import فریم‌ورک در قواعد خالص، نبود چرخهٔ وابستگی و رعایت مرزهای عمومی.
- بازیابی: قطع اجرا بین تکمیل دانلود و ورود به کتابخانه، retry و restart.

تست‌ها به آرشیو شخصی، credential واقعی یا اینترنت نیاز نداشته باشند. هیچ تستی فایل اصلی کاربر را جابه‌جا یا حذف نکند.

## تعریف اتمام
ورودی/خروجی روشن، تست موفقیت و شکست، خطا و لاگ مناسب، migration لازم، مستندات به‌روز، بررسی دادهٔ حساس و مسیرهای مخرب، عبور CI. تغییر سازگار با قراردادهای عمومی باشد؛ breaking change صریح ثبت شود.
