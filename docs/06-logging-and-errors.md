# لاگ، خطا و امنیت

## طراحی لاگر
`app/core/logging.py` مسئول تنظیم مرکزی logging استاندارد پایتون است. هر ماژول logger نام‌دار خودش را با نام ماژول دریافت می‌کند؛ handlerهای پراکنده و Singleton اختصاصی لازم نیست.

خروجی کنسول و فایل چرخشی؛ JSON برای فایل و قالب خوانا برای توسعه قابل انتخاب است. سطح، محل، سقف حجم و تعداد فایل‌ها در تنظیمات باشند. سیاست retention باید محدود و مستند باشد.

## فیلدهای پیشنهادی
زمان، level، logger، event، message و در صورت ارتباط: request_id، job_id، movie_id، source_id، download_id، duration_ms و error_code. نام رخدادها پایدار باشند، مثل `scan.started`، `scan.completed`، `download.completed` و `library_import.failed`.

شناسهٔ درخواست در middleware ساخته/اعتبارسنجی و تا مرز سرویس منتقل شود. job_id در اجرای پس‌زمینه مستقل و ثابت بماند. context در مرز thread/worker باید صریح منتقل شود؛ انتقال خودکار را فرض نکنید.

## سطوح
- DEBUG: جزئیات فنی توسعه؛ پیش‌فرض تولید خاموش.
- INFO: شروع/پایان و تغییر وضعیت مهم.
- WARNING: وضعیت غیرعادی قابل‌بازیابی، منبع قطع‌شده یا retry.
- ERROR: شکست عملیات با traceback در مرز مسئول رسیدگی.

یک exception در همهٔ لایه‌ها دوباره لاگ نشود. پیشرفت دانلود در هر tick لاگ نشود؛ وضعیت زنده از state خوانده شود.

## حریم خصوصی
API key، password، cookie، authorization header، session، query token و لینک امضاشدهٔ دانلود هرگز در لاگ نیایند. redaction دفاع تکمیلی است؛ از ابتدا دادهٔ حساس را به logger ندهید. مسیرهای شخصی و اطلاعات پروفایل نیز فقط به‌اندازهٔ نیاز ثبت شوند. تنظیمات عمومی پنل نباید secret برگردانند.

## تفکیک لاگ و وضعیت
فایل لاگ برای عیب‌یابی است؛ منبع حقیقت وضعیت Job/Download نیست. وضعیت و نتیجهٔ عملیاتی در SQLite ذخیره شوند. اطلاعات حساس exception خارجی قبل از نمایش در UI پاک‌سازی شود.

## قرارداد خطا
خطاهای قابل انتظار، نام و کد ثابت داشته باشند: SourceUnavailable، FileMissing، MatchAmbiguous، ProviderUnavailable و JobConflict نمونه‌اند، نه API تثبیت‌شده. Service خطای کاربردی ایجاد کند و Router/handler مرکزی آن را به HTTP تبدیل کند.

پاسخ عمومی نمونه:
```json
{"error":{"code":"source_unavailable","message":"منبع در دسترس نیست","request_id":"..."}}
```

traceback و جزئیات داخلی به کاربر بازگردانده نشود. خطاهای برنامه‌نویسی با except گسترده به موفقیت یا لیست خالی تبدیل نشوند.

## امنیت محلی
localhost پیش‌فرض؛ bind عمومی فقط با طراحی احراز هویت و تأیید مستقل. CORS باز راه‌حل عمومی نیست. دسترسی نوشتن از مرورگر باید در برابر درخواست ناخواستهٔ originهای دیگر محافظت شود؛ localhost به‌تنهایی مرز امنیت کافی نیست. فایل‌ها و credentialها وارد مخزن نشوند. مسیرها، ورودی پلیر و endpointهای فایل محدود و اعتبارسنجی شوند.
