# مدل دادهٔ مفهومی و قواعد هویت

این سند قرارداد مفهومی است، نه schema نهایی یا migration آماده.

| موجودیت | مسئولیت و داده‌های اصلی |
|---|---|
| Movie | هویت فیلم؛ عنوان، سال و ارتباط با metadata |
| ExternalIdentity | منبع + شناسهٔ معتبر یا URL بیرونی + Movie |
| Source | نام، مسیر ریشه، هویت اختیاری دیسک، آخرین اسکن و دسترسی |
| MediaFile | Movie اختیاری تا تعیین تطبیق، Source، مسیر نسبی، حجم و مشخصات فنی |
| PersonalState | وضعیت تماشا، امتیاز، یادداشت و منشأ داده |
| WatchEvent | تاریخ و دفعات ثبت تماشا، منشأ و شناسهٔ رویداد خارجی در صورت وجود |
| Download | Movie، کیفیت مطلوب/انتخابی، وضعیت، Aria2 GID و خطا |
| LibraryImport | وضعیت ورود فایل دانلودشده به کتابخانه؛ مستقل از موفقیت دانلود |
| Job | نوع کار، وضعیت، پیشرفت، تلاش‌ها، زمان‌ها و نتیجه/خطا |
| SyncRun | منبع، دامنهٔ دریافت، کامل/ناقص بودن و خلاصهٔ نتیجه |

## قواعد ثابت
- Movie با MediaFile یکی نیست. عنوان به‌تنهایی کلید یکتا نیست.
- چند نسخه از یک فیلم یک کارت بسازند؛ امتیاز و تماشا متعلق به Movie باشند.
- فایل ناشناخته می‌تواند موقتاً بدون Movie بماند؛ تطبیق اجباری یا حدس خاموش ممنوع.
- ترکیب منبع خارجی و شناسهٔ معتبر باید با قید یکتا از هویت تکراری جلوگیری کند.
- مسیر نسبی + Source مبنای اولیهٔ تشخیص رکورد فایل در اسکن تکراری است. تغییر نام/انتقال فایل در همان منبع نیاز به سیاست جدا دارد؛ هش کامل تمام فایل‌ها الزام نسخهٔ اول نیست.
- قواعد نرمال‌سازی مسیر و حساسیت به حروف باید متناسب با OS تعریف شوند؛ lower کردن همهٔ مسیرها راه‌حل عمومی نیست.
- ریشهٔ Source قابل تغییر باشد بدون بازنویسی هویت Movieها؛ شناسهٔ ثابت برنامه برای منبع با مسیر فعلی یکی نباشد.
- قطع منبع، MediaFileها را حذف یا مفقود علامت‌گذاری نکند. فقط اسکن موفق منبع متصل می‌تواند نبود فایل را گزارش کند.
- منشأ و زمان به‌روزرسانی داده‌های خارجی ثبت شود. امتیاز عمومی منبع و مقیاس داشته باشد؛ با امتیاز شخصی ادغام نشود.
- مشاهده‌نشدن در یک صفحه/اجرای ناقص، اثبات ندیده‌بودن نیست. وضعیت «نامعلوم/بدون ثبت» از «ندیدهٔ صریح» متمایز بماند.

## الزامات دیتابیس
فعال‌بودن foreign key، index برای جست‌وجوها و کلیدهای خارجی پرتکرار، constraint برای جلوگیری از تکرار و migration نسخه‌ای. استفاده از WAL در SQLite پس از تست محیط و هم‌زمانی بررسی شود؛ جایگزین تراکنش کوتاه نیست.

تاریخ‌ها با سیاست واحد (ترجیحاً UTC برای instantها) ذخیره شوند. تاریخ تماشای روزانه را به‌زور timestamp نکنید. بازهٔ دانلود طبق منطقهٔ زمانی تنظیم‌شده محاسبه شود، نه زمان ضمنی سرور.

## حفاظت داده
پیش از migration و ورود دادهٔ قدیمی پشتیبان بگیرید. مهاجرت از JSON قدیمی باید گزارش پیش‌نمایش، موارد مبهم و قابلیت اجرای تکراری داشته باشد؛ نام پوشه را هویت قطعی فیلم فرض نکند.
